# 语料库重复导入查重（2026-10-12）

> 状态：**方案 A 已实施**（仅本地上传防新增）。本文档保留根因定位与设计，
> 实现对失效的 manifest 条目会重新计算磁盘原件 MD5，避免覆盖后误判。
> 功能在本次合并的聊天 Agent 变更中一并交付。

## 1. 现象与结论

真机语料库出现两份内容完全相同的课件（`口腔颌面外科学 · 3 份` 中的两条 92 条内容，
文件名分别为 `(2.1.2)--第二章口腔颌面外科基本操作与基础知识` 与同名 ` (1)`），
并非该课程特例。

**结论：语料库全链路没有内容级查重。** 现有去重全部基于「文件名 / 路径」，
因此 Android 文件管理器、微信、浏览器下载、云同步盘在「目标位置已存在同名文件」时
自动追加的 ` (1)` 后缀，足以让同一份文件以两个不同 `ppt_id` 走完全流程，
产生两份 deck、两份 chunks、两份向量。

用户拍板修复范围：**A 只防新增** —— 上传时按内容 md5 查重，同内容不同文件名 → 拒收并
指向已有原件。不改建库抽取语义（避免破坏与 Python 金样的逐字节对齐）。

## 2. 根因链路（文件:行）

上传 → 落盘 → 抽取 → 入库，四段全部按名字判定：

| 环节 | 位置 | 判定依据 | 为何拦不住 ` (1)` |
|---|---|---|---|
| 上传落盘 | `app/lib/services/local/local_backend.dart:1568-1596` | 科目存在 / 文件名清洗 / 后缀白名单 / 魔数头 / 大小上限 | 只做**合法性**校验，无任何内容比对；`writeAsBytesSync` 直接覆盖同名、另存异名 |
| 树扫描抽取 | `app/lib/services/local/corpus/extract_all.dart:757-802` | `ppt_id` = 文件主干（`pyPathStem`）；同科目同名 → `-2`/`-3` 后缀 | `x.pptx` 与 `x (1).pptx` 主干不同 → 两个独立 deck |
| 入库登记 | `app/lib/services/local/corpus/extract_all.dart:1604-1628` | `deck_state` 主键 `(subject_id, ppt_id)` | 两个 `ppt_id` → 两行登记，互不覆盖 |
| 清单/缓存 | `app/lib/services/local/corpus/extract_all.dart:812-820`、`corpus_library.dart:405-424` | manifest 以**相对路径**为键 | 两个路径 → 两个条目 |

关键事实：抽取链里唯一的「同名去重」是 `ppt_id` 级（`extract_all.dart:1308-1341`
`resolvePptId`、`757-802` 同轮 `-2` 后缀），它的输入是**文件名主干**，
对「内容相同、名字不同」完全无感。

## 3. 证据

1. **本仓库自带复现样本**：`app/test/extract_all_build_test.dart:39` 引用的私有语料
   就是 `content/ppt_raw/oms/(2.1.2)--第二章口腔颌面外科基本操作与基础知识 (1).pptx`
   —— ` (1)` 后缀即系统重名改名产物，说明该现象在项目早期语料中已存在。
2. **截图数据自证**：两份都是 `92 条内容`，chunk 数逐位相同 → 正文完全一致，
   属同一文件的两次落盘，而非同名不同内容的两个版本。
3. **检索面影响**：两份 deck 都会进 `chunks`/`vectors`/`chunks_fts`，
   检索时同一段落双份命中（证据重复）、嵌入重复计费、语料库体积翻倍。

## 4. 方案 A 设计

### 4.1 判定口径

- 计算**本次上传字节**的 md5。
- 比对范围：**同一目标树目录**（`incoming/<科目>` 或 `<科目>-textbook` /
  `<科目>-exam` / `dagang-outline`）内的既有原件。跨树不比对——
  「同字节同时作课件与教材上传」按现有语义是合法的两棵树并存
  （`local_backend_test.dart:618-629` 已固化该行为）。
- 既有原件的 md5 来源分两类：
  1. **已建库**：`extract_manifest.json` 条目自带 `md5`（`extract_all.dart:815`），
     只读 JSON，不重算全库；
  2. **已落盘未建库**：manifest 里没有，按需对**待处理件**现算 md5。
     仅扫描目标树目录，不遍历整个语料库。
- 命中 → `throw ApiException(409, ...)`，消息带上已有原件的相对路径，
  便于用户定位并手动清理。

### 4.2 为何用 409

- 语义是「冲突，不是客户端错误」；`ApiClient` 的 `ApiException` 已带 `statusCode`，
  local 模式直接透传到 UI，无需改 `api_client.dart`。
- 与现有 400/413 区分，UI 可给专门文案而非「上传失败」。

### 改动 3 — 辅助函数（同文件 `_pendingIncomingFiles()`，第 1982 行附近）

```dart
/// 目标树目录名（与 upload 的 destDir 分支同口径）。
/// 同内容查重范围 = 该目录下的既有原件。
String _treeDirName(String subject, {bool textbook = false, bool exam = false, bool outline = false}) =>
    textbook ? '$subject-textbook'
    : exam   ? '$subject-exam'
    : outline ? '$kOutlineUploadCode-outline'
    : subject;

/// 在目标树内查找与 [bytes] 内容完全相同的既有原件（相对路径）。
/// 命中返回该相对路径；无命中返回 null。
String? _findSameContentInTree(String treeDir, List<int> bytes) {
  final root = Directory('$_corpusDir/incoming');
  final dir = Directory('${root.path}/$treeDir');
  if (!dir.existsSync()) return null;
  final digest = md5.convert(bytes).toString();
  // ① 已建库：manifest 条目自带 md5（只读 JSON）
  final manifest = (loadManifest('$_corpusDir/extract_manifest.json')['files'] as Map)
      .cast<String, Object?>();
  for (final e in manifest.entries) {
    final value = e.value;
    if (value is! Map) continue;
    if ('${value['md5'] ?? ''}' != digest) continue;
    final rel = e.key;
    if (rel == '$treeDir/${_baseNameOf(rel)}') return rel;   // 同树
  }
  // ② 已落盘未建库：仅对待处理件现算 md5
  for (final f in dir.listSync(recursive: true)) {
    if (f is! File) continue;
    if (!manifest.containsKey(_relPosixOf(f.path, root.path))) {
      try {
        if (md5File(f.path) == digest) return _relPosixOf(f.path, root.path);
      } catch (_) {/* 读取失败按未命中，交给后续正常流程报错 */}
    }
  }
  return null;
}
```

`md5File` 已存在于 `app/lib/services/local/corpus/py_compat.dart:299`（分块读，
不整载内存），需补 import；`_baseNameOf` / `_relPosixOf` 是 `local_backend.dart`
既有私有静态方法（2834/2838 行）。

### 改动 4 — UI 文案（`app/lib/pages/corpus_tools_panel.dart:210-218`）

在 `on ApiException catch (e)` 内加 409 分支：

```dart
on ApiException catch (e) {
  closeProgress();
  if (!mounted) return;
  final msg = e.statusCode == 409
      ? e.message                       // 「该文件与语料库已有原件内容完全相同…」
      : e.statusCode == 404
      ? '需服务器 0.3.0+，暂未部署'
      : '上传失败：${e.message}';
  TopToast.show(context, msg, type: TopToastType.info);
}
```

（409 用 `info` 而非 `error`：不是失败，是「已存在、无需重复导入」。）

## 7. 存量重复清理（截图那 3 份）

无需 SQL。走语料库页面即可，删除是跨 SQLite/文件的事务
（`corpus_library.dart:715-897`：正文、两种向量、FTS、分块状态、来源登记、原件一并清理）：

1. 进入「语料库 → 资料」，找到 `… (1)` 那份（**保留不带后缀的那份**）；
2. 点该条 → 删除 → 二次确认。确认前会重读清单并校验版本，避免误删；
3. 若列表提示「上次删除仍需清理」，先点「重试清理」再继续；
4. 完成后拉刷新，`口腔颌面外科学` 应回落为 `2 份`（1 课件 + 1 教材）。

替代路径：直接从 `incoming/<科目>/` 删掉 ` (1)` 文件后触发一次建库，
`pruneAbsent=true` 会剪除树外 deck（`extract_all.dart:1555-1582`）。
此路径不做「原件是否被其他资料共享」的保护检查，**优先用页面删除**。
