# 回炉第一批：实施与验收（2026-10-10）

状态：第一批代码与回归用例已整理，等待 CI 执行和真机验收。未提交、未推送、未打包。

## 第一批范围

- 改写 / 纠错：先生成草案，显示原卡与草案、实际引用原文及逐条拒绝理由的处理说明。
- 一拆多：2–5 张；应用时原卡归档、日志保留，子卡独立从新卡开始，整批应用在一个事务中完成。
- 暂缓 / 排除：不调用模型、不生成替代卡；仅作用于当前卡片，支持手动恢复。
- 证据选择：复用语料库，只能引用同科课件 / 教材的真实正文；固定证据优先，剩余位置用定向检索补足。
- 工作台：编辑方案、人工修订草案、明确确认后应用、撤销并恢复、查看过程记录及历史草案。

旧单卡 done 接口在本地模式返回工作台确认要求，不再直接覆盖原卡。旧待办保留迁移入口；remote/demo 的旧协议没有被假定为具备新的草案确认能力。

## 今天收尾的重点

1. 静态检查提示已清理。
2. 旧测试不再把“自动覆盖原卡”当成回炉完成；端到端与并发流水线用例已改用真实证据和草案确认协议。
3. 新回归覆盖原卡/记忆/日志保留、拆分第二张失败时整体回滚、重复应用、暂缓与排除恢复、过期方案与过期证据、无效/无变化/伪造引用输出、逐条理由未解决、模型返回时用户改动、启动失败与中断恢复等。
4. 启动失败在任务上留下可见状态；读取/刷新保留已加载任务窗口。
5. 重学恢复为数据库标准的新卡状态（稳定度、难度为空），不是写入非标准零值。
6. 题库入口可以再次查看回炉任务；运行统计区分“草案待确认”和旧的“重造完成”。过期结果不计入可确认草案数量。
