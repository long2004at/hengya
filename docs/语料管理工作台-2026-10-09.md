# 语料管理工作台（2026-10-09）

## 统一入口

- 科目首页顶部文件夹：全库资料。
- 各科目卡片文件夹：进入同一个工作台并预设科目筛选，可清除筛选查看全部。
- 设置 → 语料库与资料管理。
- 恒牙 / 关于 → 语料库与资料导入，直接进入同一工作台的「导入与建库」页。
- 原设置页的上传、建库、向量补齐/重建、诊断和原关于页的语料包导入已合并到 CorpusToolsPanel；不再保留两套实现。

## 清单与内容契约

清单取 chunks、deck_state、extract_manifest.json、incoming/ 原件、outline_entries / 大纲登记的并集；不使用检索 top-k。展示真实正文总行数与大纲总条目数。

- 保留无登记旧资料、已上传未建库、空登记、未知科目、未归属根目录文件、语料包无原件和不支持建库的原件。
- 阅读正文按页码稳定分页；搜索查询整份资料，不只搜索已加载的页面。显示已加载 / 总条数，支持继续加载。
- 可复制单段正文、通过系统分享导出 / 打开本机原件；原件缺失时明确提示，不伪造原文件预览。
- 语料包来源路径属于其他设备，不据此删除本机恰好同名的新文件。
- 大纲旧 schema 只有考试级别，没有逐条原文件归属。因此按执业 / 助理级别呈现跨科集合；关联科目筛选仍可见，删除确认明确为整个级别，而非伪装成单文件删除。
- 有目录、数据库或登记读取失败时明确标记「清单读取不完整」，保留可读部分并禁用删除；不把读取失败显示成空库。
- chunks.jsonl 是建库中间缓存，不作为第二份正式语料重复计数；删除时同步清理，避免下次建库复活已删内容。

## 删除与恢复

删除整份资料须二次确认。默认保留 hengya.db 内卡片、复习记录与原学习进度 / 章节历史；原件和语料移除后，已有卡片的来源可能失效。操作不可撤销，提示先备份。

1. 重读清单并核验版本，拒绝过期确认；共享原件归属不明确时拒绝删除。
2. 只允许操作 incoming/ 内的真实文件；拒绝路径穿越、Windows ADS、符号链接和目录链接。
3. 先准备过滤后的 manifest、分块缓存和删除日志。
4. SQLite 事务同步删除正文、向量、float32 镜像、FTS、分块状态及来源登记；大纲按级别移除相关条目与 md5 登记。
5. 数据库提交后按校验和幂等清理原件、原子替换缓存，再移除提交标记和日志。
6. 中断后启动时尝试恢复，也可在语料库点击「重试清理」。未提交日志仅丢弃暂存文件，不触碰正文和原件。原件或缓存被替换时拒绝覆盖新数据。
7. 清理未完成时禁止重新导入 / 建库，避免旧缓存把资料带回来；仍可恢复已有完整备份作为恢复通道。清理完成前不创建新的完整备份。

后台使用现有 IsolateRunner，复用 SQLite 本机加载规则。写操作持有 DataMaintenance 锁，并与建库、拆卡、语料包导入互斥。备份 / 换库也检查资料读任务，避免读取过程中换库。
